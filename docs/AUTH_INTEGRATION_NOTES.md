# 로그인·회원가입 안내 문구 점검

## 현재 동작

실제 인증 API는 없으며 화면 입력 검증을 제공한다. 로그인 화면의 대시보드 미리보기 링크는 제거했다. 회원가입 입력 완료 화면의 미리보기 링크는 유지한다. 기존에는 아래 문구가 모두 각 페이지에 하드코딩되어 있었고, API를 연결해도 자동으로 없어지는 조건은 없었다. 계정 생성이나 로그인 성공으로 처리하지 않는다.

| 위치 | 안내 | 현재 표시 조건 |
| --- | --- | --- |
| `src/pages/auth/LoginPage.jsx` / 하단 | 이용약관 및 개인정보 처리방침은 서비스 연결 시 제공됩니다. | `AuthDemoNotice` 표시 설정 |
| 같은 파일 / `submit` | 로그인할 수 없습니다. 다시 시도해주세요. | 입력 검증 통과 후 로그인 시도 |
| 같은 파일 / Google 버튼 | Google로 계속할 수 없습니다. 다시 시도해주세요. | Google 버튼 클릭 |
| 같은 파일 / 비밀번호 찾기 | 비밀번호 찾기를 진행할 수 없습니다. 다시 시도해주세요. | 비밀번호 찾기 클릭 |
| `src/pages/auth/SignupPage.jsx` / 중복확인 버튼 | 닉네임을 확인할 수 없습니다. 다시 시도해주세요. | 닉네임 입력 후 버튼 클릭 |
| 같은 파일 / 완료 화면 | 실제 계정은 생성되지 않았습니다. | 기본 숨김, 완료 단계 + `AuthDemoNotice` 표시 설정 |

## 안내 문구 표시 설정

`src/components/auth/AuthDemoNotice.jsx`를 공통으로 사용한다. 추가 요청에 따라 기본값을 숨김으로 변경했다. `VITE_SHOW_AUTH_DEMO_NOTICE=true`를 명시한 경우에만 개발 안내를 표시한다. 로그인 화면에는 대시보드 미리보기 영역이 없으며, 설정을 바꾸어도 복원되지 않는다. 회원가입 완료 화면의 미리보기 링크는 안내 문구와 분리해 계속 이용할 수 있다.

기본 설정은 다음과 같다. 기존 환경에서 `true`를 설정했다면 `false`로 변경하고 Vite를 재시작하거나 다시 빌드한다.

```dotenv
VITE_SHOW_AUTH_DEMO_NOTICE=false
```

이 설정은 수동 설정이며 API 연결 여부를 감지하지 않는다. 정적인 개발 안내만 숨긴다. API가 없는 현재 상태에서 로그인·Google·비밀번호 찾기·닉네임 중복확인을 시도하면 일반적인 실패 메시지를 표시하며, 서버 미연결 등의 구현 설명은 표시하지 않는다. 인증 성공이나 닉네임 사용 가능으로 처리하지 않는다. 회원가입 완료 화면의 로그인 복귀 링크도 유지한다.

## 실제 인증 연동 시 필요한 작업

1. `LoginPage.submit`을 로그인 API 호출, 실패 메시지, 세션 설정과 연결한다.
2. Google 버튼, 비밀번호 찾기와 닉네임 중복확인 핸들러를 각 실제 기능으로 교체한다.
3. `SignupPage.complete`에 회원가입 요청과 오류 처리를 연결하고 실제 성공 후에만 완료 상태로 전환한다. 현재는 비밀번호를 저장하지 않고 입력만 정리한다.
4. 공통 인증 상태, 페이지 접근 제어 및 로그아웃을 연결한다. 미리보기의 `/dashboard` 링크는 현재 인증 세션을 생성하지 않는다.
5. 실제 이용약관·개인정보 처리방침 링크와 가입 완료 문구를 제공하고 개발 안내의 기본 숨김을 유지한다.

이번 변경은 인증 API나 localStorage 데이터 구조를 수정하지 않는다.

계정 설정(`src/pages/profile/MyPage.jsx`)의 `로그인 화면으로`는 `로그아웃`으로 변경했다. 기존 `/login` 이동을 유지하고 과목·코인·구매·착용 데이터를 삭제하지 않는다. 실제 세션 해제는 인증 API 연동 시 연결해야 한다. 비밀번호 변경 및 프로필 저장 안내에서도 서버 미연결 설명을 제거했다.

아래는 직전 대시보드 작업의 검증 기록이다.

- Edge에서 PC·402px·320px·768px 회귀 검사 48개 통과. 알림은 375px에서도 별도 검증했다.
- `VITE_SHOW_AUTH_DEMO_NOTICE=false` 조건의 인증 검사 8개 통과.
- 최종 짧은 일정 표시 보완 후 대시보드 검사 20개 재실행·통과.
- 5·7개 과목의 내부 스크롤, 제목 고정, 휴강 처리, 과목 홈 이동 및 새로고침 후 상태 유지 확인.
- 21–23시 일정 추가·저장, 20:30 시험의 위치·높이, 23:30 시험 표시, 요일 헤더와 열 정렬 확인. 모바일은 브라우저의 터치 이벤트로도 스크롤을 검증했다.
- 스크린샷: `artifacts/dashboard-ui/`. 실제 휴대전화 기기 검사는 수행하지 않았다.
- `npm run build`, `npm run lint` 통과. 빌드에는 500kB 초과 번들 경고가 남아 있다.

시간표 기본 구간은 기존의 09–20시이며, 일정이 있으면 해당 시작·종료 시각까지 확장한다. 시험에는 종료 시각 필드가 없어 기존 1시간 표시를 유지하며, 자정 이후로 넘어가는 부분은 당일 24시에서 끝낸다. 일반 일정은 저장된 시작·종료 시각을 그대로 사용한다.
